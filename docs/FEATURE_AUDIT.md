# Feature availability audit

Every feature is admissible only if its value could have been known at the end of the vulnerability's `snapshot_month`. This table is generated by `python -m pipeline.audit`.

Features in the final model: **73**.

| Feature group | Source | Calculation | Available at snapshot | Leakage risk | In model | Justification |
|---|---|---|---|---|---|---|
| **calendar** (4) | vulnerabilities.csv (published) + snapshot_month | Publication month, day-of-week, day-of-month, and days between publication and snapshot month end | yes | none | yes | Timestamps known at publication and at the snapshot boundary |
| **cvss** (14) | vulnerabilities.csv CVSS 3/2/4 fields | Numeric components and CVSS vector decomposition; missing values median-imputed before the model sees them | yes | medium — blank severity is itself a NIST-review signal, so a tree must not be able to split on 'missing'; the imputer removes that split | yes | Severity components are the baseline comparator; missingness is filled, never encoded |
| **epss_exploit** (10) | exploit_signals_2024/2025.csv (train) and scoreboard_2026.csv (predict) | EPSS score, logit, within-month percentile, missing flag; Exploit-DB / Metasploit / Nuclei / GitHub PoC flags | yes | none — these files are exactly the state at month end by construction | yes | Only source of public-exposure evidence that is provably as-of |
| **vendor_history** (8) | vulnerabilities.csv assigner + known_exploited.csv date_added | Vendor key from the CVE assigner domain; KEV counts and rates computed with date_added <= month end; 90/365-day recency windows | yes | low — assigner is fixed at ID reservation; the CISA-ADP GUID assigner is collapsed to a neutral key because ADP enrichment is applied after publication | yes | 84% of KEV entries come from vendors already represented in KEV |
| **text** (30) | vulnerabilities.csv description | Length/word counts and 28 regex indicators (RCE, deserialisation, auth bypass, ...) | yes | low — descriptions are written at publication; a minority are edited later, so keyword rates are a lower bound | yes | Descriptions carry wording that CVSS does not encode |
| **interactions** (4) | derived | epss x exploit-code, WordPress-ecosystem and GitHub-CNA flags, 'silent critical' flag | yes | none — products of already-validated features | yes | Captures conditional effects additive models miss, with no new data dependency |
| **horizon** (1) | snapshot_month + evaluation cutoff | Days from snapshot month end to the evaluation cutoff (2025-12-29 for train, 2026-11-04 for the competition) | yes | low — the cutoff is a published competition rule, not per-CVE information | yes | Exposure windows differ by cohort; without it the model cannot distinguish a 10-month from a 1-month window |
| **granite** (2) | ibm-granite/granite-embedding-30m-english over CVE descriptions | Max and mean-of-top-5 cosine similarity to KEV descriptions added BEFORE the row's snapshot month end | yes | none — the reference set is nested by month; future KEV additions are masked out | yes | Adds a semantic signal that is independent of CVSS and EPSS |

## Deliberately excluded columns

| Column | Why it is unsafe | Decision |
|---|---|---|
| `nvd_status` | NIST reviews attacked CVEs first; status is a post-hoc signal | Excluded from all features |
| `n_affected_cpes` | CPE rows are added during NVD analysis; 49.6% of the 2026 pool is blank | Excluded |
| `n_references` | Reference count grows after exploitation is reported | Excluded |
| `references.url / domain / tags` | News and threat-research links are added after attacks; 37,853 IBM X-Force links alone | Summarised for the audit only, never a feature |
| `blank cvss3_score as signal` | Blank severity means NIST has not reviewed the record yet, and NIST reviews attacked CVEs first | Median-imputed before the model sees it; no missingness indicator |
| `cwe_ids missingness (cwe_missing, has_cwe_* dummies, cwe_kev_rate_*)` | CWE is assigned during NVD analysis, so a blank weakness class carries the same review-status signal as a blank score | Dropped from the model entirely: the model was selecting only reviewed CVEs |
| `last_modified` | Every row is stamped mid-2026 or later | Excluded |
| `assigner == CISA-ADP GUID` | ADP enrichment is applied after publication | Collapsed to a neutral category |
| `affected_products vendor/product` | CPE coverage itself leaks NVD attention | Excluded from the model; used only in EDA |

## Notes

- CWE features are not in the model: blank CWE tracks NIST review, and a multi-hot encoding makes 'no weakness class' a distinct, learnable pattern.
- Text indicators (28): kw_auth_bypass, kw_buffer_overflow, kw_cmd_injection, kw_csrf, kw_dependency, kw_deserialization, kw_dos, kw_file_upload, kw_hardcoded, kw_info_disclosure, kw_integer, kw_kev_ref, kw_open_redirect, kw_path_traversal, kw_priv_esc, kw_prototype, kw_race, kw_rce, kw_sqli, kw_ssrf, kw_template_injection, kw_unauthenticated, kw_use_after_free, kw_wormable, kw_xss, kw_xxe, kw_zero_click, kw_zip_slip
- Proc- and CPE-derived vendor/product features are excluded from the model because 49.6% of the 2026 pool lacks them for reasons that correlate with NVD attention.
- Exploit-signal files cover 2024-01 to 2025-12 only; 2023 cohorts are therefore excluded from training rather than imputed, because a fully-missing EPSS column is not a neutral imputation.
